# 00 · 第一性原理与过滤准则

## 1. 记忆 / 知识系统要解决什么？

从认知与工程双侧收敛到两条：

| 原理 | 含义 | 本仓对应 |
| --- | --- | --- |
| **清晰高熵存储** | 每条资产边界清楚、可寻址、可追溯、不与其它条目糊成一团 | Markdown + YAML front matter；id；分层目录；晋升门禁 |
| **高效检索 + 智能联想** | 不但「搜到」，还能「想到相关」 | tag-graph BFS / associate；未来 weight、时间、可选语义 |

**推论：** 优化主轴是「在保持存储清晰与可审的前提下增强检索与联想」，而不是把真源搬进不可 Git 的重型库。

## 2. 本仓问题定义（与竞品切割）

| 本仓要回答 | 本仓不主责 |
| --- | --- |
| 团队规范/错题/决策如何版本化、投影到多 Agent？ | 跨会话「越用越懂用户」的 SOTA 学习记忆 |
| 如何用人审门禁防止 Agent 静默改章程？ | 百万文档语料的全局社区问答 |
| 如何用轻量 tag 网做人类式联想？ | 桌面级「扫所有 AI 工具历史」的偏好快递 |

## 3. 借鉴过滤准则（硬规则）

对每个竞品机制问四问，全过才进入推荐：

1. **赛道匹配？** 是否服务「工程真源 / 轻量联想」，而非要求本仓变成对方产品  
2. **底线兼容？** 是否破坏：轻量默认、Markdown/Git、晋升门禁、三层布局、本地可控  
3. **可渐进？** 能否默认关闭 / dry-run / core_write 闸门  
4. **证据充分？** 是否来自对方公开 README/文档/数据流，而非传闻

## 4. 涌现论在本仓的合法用法

原始 opt-plan 主张「不要预设 L0–L3，让 tag 网长出结构」——**部分成立**：

- **成立：** 联想拓扑适合生长；查询时可动态分层（借 OpenViking「渐进加载」思想，但不必写入钉死目录层）  
- **不成立：** 工程知识仍需要 **rules / lessons / templates / decisions** 这类**制度分层**（这是门禁，不是图论层级）  
- **折中：** 制度分层（目录）× 联想分层（tag 网）× 加载分层（查询时 L0/L1/L2 摘要深度）三正交

## 5. 成功判据（第一性）

| 判据 | 可观察信号 |
| --- | --- |
| 存储更清晰 | 条目有 id/tags/时间/可选 channel/evidence；无静默改 rules |
| 联想更强 | expand 使用 weight；孤岛下降；associate 可解释路径 |
| 检索更省 | 渐进加载 / 时间窗减少无关正文 |
| 仍可维护 | 默认可无 Docker/向量跑通 P0；生成物可删可重建 |
