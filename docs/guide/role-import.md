## 导入分层

导出目录中的文件按职责归位，不把整份导出当作每次启动的系统提示。

- 稳定设定：AGENTS、IDENTITY 及可选 SOUL、USER、TOOLS，保留职责、风格和实际执行约定。USER 可说明档案使用边界，历史身份、持仓和客户事实不自动成为当前用户事实。
- 活动技能：只注册适合该角色的候选入口。长方法与静态脚本、模板、字体等支持文件按清单投影；技能入口存在不代表其服务、依赖或权限可用。
- 长期知识：方法、纠错和决策进入自身 notes，保留来源、时点、项目与确定程度。自己的 graph 和 summary 用于后续任务检索，不改变执行权限。
- 项目历史与可变记录：原文、数据、草稿、客户档案、学情、反馈和旧日志保留项目范围，经 task.files 明确选择后读取。
- 本机运行状态：客户端、凭据、缓存、锁、临时工作区和执行收据放 runtime／generated，不写入角色长期版本。

同一资料只保留一个正文来源；索引、技能和摘要以来源路径与指纹关联。流程说明可以逐步演化，过去任务的主体、结果和时间线留在对应来源或项目记录。

历史教训与流程迭代记录按内容归位，不能因为目录名含 logs 就整类视为缓存。初始化角色图时可建立自己的专业标签关联和中英文同义词，再构建条目索引；保留已有关系。边权只用于检索排序与展开，不表示事实置信度、专业能力或现实预测准确率。

## 角色目录与标签

role.yaml 的 tags 描述角色领域和任务类型，帮助协调者缩小候选目录。它与 task.tags 分工不同：前者用于找角色，后者用于本次技能选择与双路知识联想。

```text
ygg role list --brief
ygg role list --brief --tag research
ygg role list --brief --tag research --tag data
```

多个 --tag 采用全部命中。--brief 返回较小的角色目录；筛选不执行模型、不读取另一角色记忆、不授予工具或共享资料权限。明确选定角色后，再用 prepare 或 run 建立该角色的任务上下文。

角色标签可写为：

```json
"tags": ["research", "data", "review"]
```

标签是否命中只表示目录相关性，不证明角色更权威或任务已完成。

## 技能静态资源清单

SKILL.md 的 metadata.resources 明确声明该技能需要投影的静态支持文件或子目录。路径相对技能根，必须真实存在并留在该根内；声明子目录会包含其安全文件树。

```yaml
---
name: evidence-review
description: 检查研究输入的来源、完整性和口径。
metadata: {"tags":["research","review"],"requires":["python"],"availability":"method-only","resources":["references","scripts/check_inputs.py","LICENSE"]}
---
```

示例路径只是契约示意，实际声明按技能已有文件填写。metadata 可采用 YAML 映射或单行 JSON 映射。

- resources 未声明：使用现有安全扫描方式发现支持文件。
- resources 为 []：只提供技能入口，不投影支持文件。
- resources 为非空列表：只投影所声明的单文件或子目录；缺失、越界或含禁项的声明报错，不静默扩大到全目录。

声明子树中出现链接、凭据、缓存、node_modules 或归档等禁项会拒绝该声明。作者应选择具体静态文件或干净子树，而不是把整个工作目录作为支持资源。

客户资料、学情、生成反馈和用户 profile 即使不是禁项，也属于可变记录，不应列入静态资源。安全路径校验不能自动判断所有文件的业务含义，导入时仍需按职责审查。目录名为 data 不决定其类型：固定模板可以是静态资产，真实业务数据应归项目。

## 历史资料与可变记录

导入历史可保存在角色自身的项目中：

```text
roles/<role-id>/
  role.yaml / AGENTS.md / IDENTITY.md
  skills/<skill-id>/SKILL.md
  memories/notes/                 方法、纠错、来源和决策
  memories/graph/                 自身图与索引
  memories/summary.md             跨项目短摘要
  projects/<import-id>/
    STATE.md                     导入状态、验证边界和待办
    manifest.json                原路径、目标路径、哈希与处置
    source/                      保留原资料相对层次
```

此目录是存储示意，导入工具按实际职责生成文件。原文与适配入口分开保存：原文用于追溯，适配入口用于当前任务。非活动技能和旧运行说明可以保留为历史资料，不因此自动注册或执行。

任务绑定已注册项目后恢复 STATE 和文件清单，实际脚本、数据、客户或学情资料仍通过 files 明确选取。已导入、文件存在、状态恢复与研究复算、成绩提交、客户判断完成是不同状态。

项目限定经验可以进入自身 notes，但保留 project_id；跨项目 summary 不全量吸收客户记录、持仓、成绩或历史市场结论。共同经验另行形成获准共享条目，不能直接将整角色私有树镜像为共享知识。

## 增量合并与来源

重复导入先识别角色与项目，再比较来源指纹。相同源同哈希可复用；同名不同内容保留差异和迁移记录，按当前角色约定适配，不覆盖已经核验的配置、技能、项目和记忆。

manifest 应记录角色映射、原路径、目标路径、源／目标指纹、适配原因、许可、排除项及验证状态。文件名乱码只有在编码恢复可逆且无路径冲突时修复，并同时保留原路径；无法确认时记录原名，不靠视觉猜测。

凭据不迁入长期版本；涉及脱敏的正文记录处置和新指纹，不在记录中复述原密钥。被用户明确排除的资料记录排除原因，不自行转换、补造或改名冒充另一来源。

许可按文件或技能实际来源保留。MIT、非商业、专有和未指定许可分别标识；不能把整个导出统称开源或已获商用权。

## 验证与能力状态

至少核对角色配置、技能入口及资源声明、JSON／脚本静态结构、图与摘要的一致来源指纹、项目范围和准备快照。适配过的可执行脚本在真正使用前另行验证，静态检查不证明业务结果正确。

真实模型执行记录 backend、请求隔离与实际隔离；prepare 只准备上下文。enforced 只声明实际落实的文件范围限制，不自动变成网络隔离；原生 subagent 的逻辑准备不承担操作系统访问隔离。

工具目录分别说明方法、依赖、安装、授权与真实业务验证。未登录或未授权服务保留缺口，不自动认证、上传材料或用模型生成数据替代。导入本身不执行研究、发信、预约、投递、发布或媒体生成。
