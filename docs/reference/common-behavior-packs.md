## 1. 目的

`YggForge` 不只是知识仓库，也要承担“全局控制层”的一部分职责。

因此需要一类内容：

- 很短
- 高约束
- 低 token
- 可跨 Agent 复用

这类内容放在：

- `profiles/common/behavior-packs/`（相对 `yggforge-core/`）

## 2. 为什么不直接全放进 rules

`knowledge/rules/` 是知识真源，适合沉淀完整规则。

但部署到全局 Agent 入口时，还需要更短、更适合被投影的形式：

- 作为 render 素材
- 作为全局行为基线
- 作为不同 Agent 的共同“执行纪律”

所以行为包和规则真源应并存：

- 规则是真源
- 行为包是投影友好的短入口

## 3. 当前行为包

目前已有：

- `profiles/common/behavior-packs/karpathy-guidelines.md`

它对应的 canonical source 是：

- `knowledge/rules/agent-coding-discipline.md`

## 4. 推荐使用顺序

对于支持投影入口的 Agent，推荐：

1. 先加载行为包
2. 再加载 `knowledge/rules/`
3. 再按需读取模板、经验、决策

## 5. 适合做成行为包的内容

- 不要静默假设
- 优先简单方案
- 只做手术式改动
- 目标驱动、可验证执行
- 遇到歧义先停下说明

## 6. 不适合做成行为包的内容

- 语言细节风格
- 项目特定约束
- 长篇背景说明
- 大量案例与反例
